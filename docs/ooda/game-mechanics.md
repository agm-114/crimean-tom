# Sea Power mechanics for OODA

These paths come from the installed `Sea Power_Data/Managed/Seapower-Scripts.dll` (SHA-256 prefix `46D765D07124C801`). They were traced with ILSpy. Check behavior in the game before treating a new adapter as equivalent to a player command.

| Area | What the installed code does | What OODA should use |
| --- | --- | --- |
| Tactical map | `SceneMapViewModel` creates `MapKnownUnits` for the player task force. `MapKnownUnits.AllUnits` starts with its `PlottingTable.Vehicles` and filters with `Vehicle.IsVisible()`. `MainGameViewModel.NavigateToContact` checks membership and visibility again. | Scope all lookups to that task force's plotted tracks. Resolve contact IDs in that same view. Keep the real objects behind the tracks inside the command adapter. |
| Track quality | `Vehicle.PositionEstimate` returns a fresh detected position or an extrapolated one. `HasLiveTrack` distinguishes the two. `BaseVehicleViewModel.UpdateFrom` presents detection age, tracking status, and detected/classified/identified labels. `Vehicle.CurrentRelationship()` uses a detected task force or a manual posture override, and otherwise returns unknown. | Export nullable position, freshness, displayed posture, and the displayed type or identity when available. A bearing-only or dormant track can guide search, with its uncertainty intact. Keep the player-set posture distinct from positive identification so the model cannot manufacture authorization by relabeling a track. |
| Ownership | `ObjectBase.AcceptsOrdersFromPlayer` accepts player units and can also accept enemies when the debug override is set. `UnitSelectedState.MouseDown` checks `isUnit()` and `AcceptsOrdersFromPlayer`. The map waypoint branch also checks `IsControllable`. | Require the exact authored task force, a live unit, and the native action's commandability checks. Recheck the effective recipient if the game forwards an order to the formation leader. |
| Waypoint | `UnitSelectedState.HandleUnit` treats an ordinary map waypoint as a replacement. It can forward to the formation leader, clear a current order, detach a patrol assignment, and apply the user's waypoint/Weapons Free behavior before clearing and replacing the route. Shift-click appends under different conditions and rejects appending to a loop. | Give append and replace distinct meanings. Trace the side effects of an ordinary surface waypoint first, then compare recipient, route, existing order, and weapons posture against a manual click. |
| Identification | `UnitSelectedState.HandleUnit` routes a normal click on an unidentified track to its identify order. `MapUnitViewModel.GetContextMenuItems` separately offers a radio identification request. `CommunicationResult` requires an authored player sender, checks submergence, line of sight and communications horizon, and can report ignore or refusal. The request can reveal the sender to the recipient. | Treat a hail and a scouting approach as different choices. Radio silence can result from several conditions. An identify order may move the assigned unit, so protect the escort or patrol assignment while it investigates. |
| Weapon order | `WeaponEntry` starts `AttackingState`. Its map handler checks whether the selected ammunition and seeker match the target and whether required support exists. `NormalAttack` can issue the order to several formation members. `AddAttackTask` queues the ammunition, target, and salvo. `ObjectBase.GetMaxEngagementRanges` supplies data for the player preview. | For the last-salvo test, verify a single-ship firing path with the same native checks and a bounded shot count. Require a current Blue track and mission authorization before evaluating that path. Log when the order is queued and when a launch is observed. A queued attack can still wait for its firing conditions. |

`ObjectBase.HandleEngageTasks` checks the soft-kill reaction delay and launcher readiness for a native chaff engagement. The game has standing orders at force, formation, and unit level. The last-salvo decision should read the effective posture and verify whether a shot is still available while those defenses continue. [Triassic Games on standing orders and electronic warfare](https://www.microprose.com/news/sea-power/sea-power-update-0-8-3-campaign-updates-new-command-tools-combat-overhauls)

For the first live check, compare a visible unknown and a dormant track with the tactical map and contact-information panel. Confirm that a guessed ID for a hidden contact gives the same result as a missing ID, and that a friendly ship outside the authored task force stays outside OODA's command set. The [Game Bridge world snapshot](../../src/SeaPower.GameBridge/UnitSnapshot.cs) can serve as the developer's comparison for this test.
